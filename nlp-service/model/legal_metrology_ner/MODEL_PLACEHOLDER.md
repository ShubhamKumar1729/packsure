# MODEL PLACEHOLDER — no trained model exists yet

**Status: NOT TRAINED.** There is deliberately no model binary in this directory,
no fake weights, and no invented accuracy metrics anywhere in the repository.

This directory (`nlp-service/model/legal_metrology_ner/`) is where the trained
token-classification artifact produced by the Google Colab pipeline must be
placed. Until then:

- `GET /health` reports `"model_loaded": false` (status `degraded`).
- `POST /extract` and `POST /pipeline` use the transparent deterministic
  **pattern extractor** and every response is marked
  `"extractor": "pattern_rules", "degraded": true`.
- Nothing in PackSure pretends the model exists. The frontend shows a
  degraded-mode banner whenever `degraded` is true.

## What to copy here after training (see docs/ML_TRAINING.md)

```
model/legal_metrology_ner/
├── config.json              # HF model config
├── model.safetensors        # trained weights
├── tokenizer.json           # fast tokenizer files
├── tokenizer_config.json
├── vocab.txt / special_tokens_map.json (as produced by the base model)
└── label_mapping.json       # {"labels": [...], "label_to_id": {...}, "id_to_label": {...}}
                             # (generated by notebook 03; REQUIRED)
```

Then set `MODEL_VERSION=x.y.z` in the service environment to advertise the
artifact version in every response, and restart the service.

`label_mapping.json` must contain exactly the 16 entity labels from
`app/entities.py` / `ml/config/labels.json` — the loader validates nothing
silently: a mismatched label set will be used as-is, so run the service tests
(`pytest`) after copying a new artifact.
